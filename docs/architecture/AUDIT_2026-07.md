# DPA ECOSYSTEM AUDIT — JULY 2026

**Scope actually inspected:** the full GitHub repo (all code + all docs), the live web app source, the Notion Command Center (home page, Operating Manual, System Documentation & Roadmap page, and schema-level inspection of Content Ideas, Projects, Tasks, Knowledge Base, AI Agents, Automation Dashboard, plus row-level spot-check of Content Ideas).
**Not inspected (declared honestly):** row-level contents of the other 13 Notion databases (mostly empty per the phased plan), Google Drive (tool permission failed during audit), Vercel deployment logs, the founder's n8n/ChatGPT/Gemini accounts. Re-audit those when they hold real data.

**Overall verdict:** each subsystem is individually well-designed. The ecosystem-level defect is that there are now **two operating systems built by different AI sessions that don't know about each other** — the GitHub governance/brand stack and the Notion Command Center. Everything Critical flows from that.

---

## CRITICAL

**C1 — Split-brain ecosystem (the finding that matters most).**
The repo contains doctrine, brand, scripts, engineering rules, priorities, and a changelog culture. The Notion OS contains execution databases, its own Operating Manual (SOPs), its own architecture map, its own phased roadmap, and its own changelog rule. **Neither system references the other anywhere.** Consequences already visible: two SOP sets, two roadmaps with different Phase-1 definitions (repo: launch YouTube; Notion: ship CLIPFORGE Etsy listing #1), two content-pillar taxonomies, and a future AI session's behavior depending entirely on which door it happens to enter through.
*Fix (order matters):* (1) declare the split of authority — **repo = doctrine layer** (constitution, brand, engineering, AI governance), **Notion = operations layer** (projects, tasks, content pipeline, finance, journal); (2) add a Doctrine card to the Notion home page linking CLAUDE.md, the founding docs, and the brand bible; (3) add Notion links to the repo's AI_ONBOARDING reading list (done in this audit's PR via SYSTEM_OVERVIEW + DOCUMENTATION_INDEX); (4) the founder reconciles the two Phase-1 priorities into one sentence (they are compatible — Etsy = revenue now, YouTube = brand engine — but *sequence and hours* must be explicit).

**C2 — Content pipeline desync.**
Repo: 30-video backlog with hooks/mechanisms/thumbnails + 4 production-ready scripts. Notion Content Ideas: 3 rows (1 template + 2 ideas), no links to the repo scripts, and "Why Smart People Procrastinate" marked **Idea** while its finished script sits in `youtube/scripts/01-*.md` at status render-ready. Whoever opens either system gets a false picture of content state.
*Fix:* import the 30 backlog entries into Content Ideas (Title, Pillar, Priority, Format=Video, Platform=YouTube; Notes = one-line hook; Link = GitHub URL of script where one exists; Status = "Ready to Script"→actually "Ready to Record" for 01–03 — set 01–03 to Ready to Script/Recording per reality). One-time import; ~30 rows; an AI session can do it in minutes with founder approval.

**C3 — Paid media assets still unarchived (repeat finding, still open).**
The key art PNG and 5s ident MP4 exist only at Higgsfield CDN URLs that can expire; they cost real credits and are referenced by the trailer plan. *Fix:* download both, store in Drive + optionally repo `assets/` (image yes; video judgment call on size), record final locations in `youtube/PRODUCTION_ASSETS.md`. This has been the #1 action item across two sessions; it is a five-minute task.

**C4 — Production chat is likely broken.**
`api/chat.js` calls model `claude-sonnet-4-6`, which does not match any current Anthropic model ID. If so, every visitor to the deployed site gets an error from the chat box — the site's only interactive feature. *Fix:* one-line change to a current model ID + actually exercising the chat on the preview deploy. (Tier-1 code change; any AI session may do it.)

## HIGH PRIORITY

**H1 — Taxonomy drift (three competing content-pillar vocabularies).** Constitution: 5 pillars (Cognitive Performance, Human Behavior, AI Mastery, Entrepreneurship, Personal Growth). Notion Content Pillar select: 8 options (Human Behavior, Attention & Focus, Decision Making, Learning, AI, Entrepreneurship, ADHD, Automation). Repo YouTube strategy: series names (Observatory/Forge/etc.). *Fix:* keep Constitution pillars as the canonical top level; treat Notion's 8 as sub-topics; add a mapping table (now in DATABASE_SCHEMA.md §4); rename nothing in bulk until the founder approves.

**H2 — Web app security/privacy (repeat finding).** CORS `*` + no rate limiting = anyone can spend the Anthropic budget; founder's personal profile in client-side source. *Fix bundle (single small PR when founder green-lights):* lock CORS to site origin, move SYSTEM prompt server-side, add trivial per-IP rate limit, fix model ID (C4).

**H3 — Duplicate self-relation in Projects.** Both `Related Projects` and `Related To` exist (same target, same purpose). Every duplicated relation doubles linking ambiguity forever. *Fix:* founder picks one (recommend `Related Projects`), migrate any values, delete the other. Do it now while databases are near-empty.

**H4 — Inconsistent AI-assignment modeling.** Projects→`AI Assigned` is a relation to AI Agents (correct); Tasks→`AI Responsible` is free text (drifts instantly). *Fix:* convert Tasks' property to a relation to AI Agents; free text becomes unqueryable the day two spellings of "Claude" exist.

**H5 — No backup story.** Notion: no export schedule. Repo: no branch protection on auto-deploying `main`. Vercel: env key exists in exactly one place. *Fix:* monthly Notion workspace export to Drive (calendar SOP, later n8n); enable GitHub branch protection requiring PRs on `main`; note key restore path in Assets DB (name/reference only, never the secret).

**H6 — The Etsy/CLIPFORGE business exists only inside Notion.** The repo's PROJECT_CONTEXT knew of it only via the site's system prompt; the Notion OS treats it as Phase-1 flagship. If Notion is lost, the actual current business plan is lost with it. *Fix:* C1's doctrine/operations split plus the monthly export covers this; also one paragraph in PROJECT_CONTEXT (added in this PR).

## MEDIUM PRIORITY

**M1 — Knowledge Base `Category` mixes two taxonomies** (topics like Psychology with formats like Books/Quotes/Research Papers). Splitting later costs re-tagging 10,000 entries; splitting now costs one property. *Fix:* add `Type` select (Note/Book/Paper/Quote/Framework/Mental Model), keep `Category` purely topical.
**M2 — Time fields are text** (Tasks Estimated/Actual Time, Content Watch Time) so they can never roll up. *Fix:* convention = integer minutes in Number properties; rename `Estimated Min`/`Actual Min`.
**M3 — Progress is manually typed** on Projects though the Notion doc itself contains the correct rollup recipe. *Fix:* apply the documented rollups in-app (API can't; 15 minutes by hand).
**M4 — Template rows not yet native templates** ("📋 TEMPLATE — duplicate me" pattern). Works, but one mis-edit corrupts the master. *Fix:* convert to native database templates in-app as the Notion doc already prescribes.
**M5 — Repo hygiene:** no LICENSE (all-rights-reserved implied — fine, but decide), no `.gitignore` (harmless today; add `node_modules/`, `.env*`, `.vercel/` preemptively), no PR template.
**M6 — Cosmetic:** home/manual/doc page titles render doubled emoji ("🐉 🐉") — icon set *and* emoji in title text; drop the emoji from title text.
**M7 — Status vocabulary near-misses across DBs** (Idea/Building/Live/Paused/Retired vs Concept/Building/Deployed/Retired vs Upcoming/Active/Waiting/Completed). Acceptable — different lifecycles — but documented now in DATABASE_SCHEMA so nobody "harmonizes" them accidentally, and new DBs must reuse an existing vocabulary where one fits.
